Last.fm

Powers start-from-a-song queues, dynamic and pinned stations, and search-result discovery. Get a free key →

Discovery is off. Octo needs a free Last.fm API key to find and recommend music. Without it, search and radio only return what's already in your library. The steps are below.

Account

Octo talks to Last.fm through a free API app of your own. Save checks both values with Last.fm first.

Make your Last.fm API app

  2. Any name will do, such as Octo. Leave Callback URL and Application homepage empty.

Already made one? Your apps are listed on API accounts. If yours shows no shared secret, make a new one.

Radio basics

Song radio is a one-time queue requested by a client. Dynamic and pinned radio are reusable stations.

Enable Last.fm radio
Master switch for start-from-a-song queues and all dynamic or pinned stations.
Tracks per station or queue
Maximum tracks in start-from-a-song queues and in dynamic or pinned station snapshots.
Last.fm lookup cache (hours)
How long Octo reuses recommendation responses across radio features.
Wait for a cold station's first track (seconds)
A station with nothing cached yet needs a fetch and a transcode before it can play. The station list answers within this bound and the station appears on the next refresh. 0 waits however long it takes. Default: 8.
Radio loudness target (LUFS)
Every radio track is brought to this EBU R128 loudness before it joins the stream, so local files and previews play at one level. -16 suits headphones and speakers; -14 is what most streaming services use. 0 turns it off.
Refresh stations every (hours)
Rebuilds dynamic and pinned station queues in the background. The current snapshot stays playable until its replacement is ready. Default: 12 hours.

How stations play

Applies to dynamic and pinned stations only. Enable either playback method or both; song radio remains a client-created track queue.

Playlist method
Shows each station in the client's Playlists section. This provides full track controls and preserves normal local-song quality; heart a discovery track to fetch a permanent lossless copy.
Streaming method
Shows each station in the client's Radio section as one continuous MP3 stream. Tracks are transcoded to the quality selected below.
Radio streams cannot add songs to your library. A client sees one continuous stream rather than individual songs, so liking or hearting the current track cannot trigger an Octo download. Open the station in Playlists when you want to heart a song and add it.
Internet radio quality
MP3 bitrate for new continuous streams. Reconnect to apply a change. This does not affect playlist playback or downloaded quality.
Now-playing metadata
Embeds Octo's existing station artist and title in the MP3 stream for radio clients that request ICY metadata. Reconnect after changing this setting.

Dynamic stations

Builds read-only stations from each listener's completed plays. Listening history stays private in Octo.

Enable dynamic stations
Starts with Starter Radio, then grows into Your Mix, discovery, artist, and genre stations.
Your Mix
The listener's own mix, drawn from what they actually play. Before Octo has learned enough this is Starter Radio, which is the only station a brand-new listener gets.
Discovery Mix
One station of less-familiar music, seeded from the listener's most-played tags.
Artist stations
One station per most-played artist. Set to 0 to build none.
Genre stations
One station per top tag in the listener's history. Set to 0 to build none.
Discovery balance
Percentage of Your Mix reserved for less-familiar recommendations.
Personalization threshold and history
Completed plays before Your Mix
Before this many completed plays, Octo offers Starter Radio. Afterward it can build Your Mix plus discovery, artist, and genre stations. Default: 10 plays.
Keep completed plays for (days)
Older plays stop influencing dynamic stations and are removed from Octo's local listening history. Downloaded music is unaffected. Default: 90 days.

Tags & genres

How Octo tags what it downloads, and a tool that applies the same genre rules to music already in your library.

Metadata

Tag language
Language for genre and other text fetched from metadata providers (Deezer, Last.fm) and written into a download's tags. Without it, providers pick a language from the server's IP address. Two-letter code like en, de, fr; empty lets the provider decide. New lookups use it right away; results cached in the last 12 hours keep their old language until they expire. Cover art picks up a new language after a restart.
File singles under their title
A download whose source, Deezer and its own tags all name no album is filed as a single under its title, instead of joining the one “[Unknown Album]” Navidrome gives every album-less track. Never applied to a compilation.
Cover Art Archive first
When a fingerprint named the release, ask the Cover Art Archive for its cover before Deezer, iTunes and Last.fm: the right pressing, no guessing by name.
Replace video covers
A cover that is not square is a video thumbnail, so it counts as missing. When nothing better turns up, its centre square is used, which for a YouTube “Topic” upload is the real cover inside the letterbox.
Write cover.jpg
Also put the cover beside the file, where Navidrome reads it first. Only in the Organized layout, and only in a folder the download created, so an album that was already there never changes cover.

Lyrics

A lyrics file beside each download, which Navidrome serves without a rescan, and lyrics for any song as it plays when your library has none, in every app. Synced lyrics go in a .lrc, plain ones in a .txt; lyrics timed word by word are still a normal .lrc that any player shows line by line. A file that already has lyrics is never touched.

Fetch lyrics
Looked up in the background after a download finishes, so a slow lyrics service never holds up the next one.
Sources in order
Asked from the top down. Drag to reorder, or use the arrow keys on the handle. A source that is off is never contacted.
Prefer word-timed lyrics
Lyrics timed word by word beat lyrics timed line by line from a source higher up. Off, the first timed lyrics win, which asks fewer services per song.
Write lyrics files beside all library songs
Off, “Find lyrics for the library” only writes beside songs Octo downloaded. On, it also writes beside your own rips and purchases. Existing lyrics files and lyrics inside a song are never replaced either way.

Find lyrics for the library

Looks up lyrics for songs that have none, one song at a time with a pause between, and writes a lyrics file beside each one found. Stop it whenever you like and resume later from where it was.

Also look for word timing
Octo's own line-timed lyrics files are looked up again and replaced when word-timed lyrics turn up.
Songs Octo downloaded
Turn on “Write lyrics files beside all library songs” above to include the rest.
Review
Lyrics written where the match was not certain, most often because a length could not be checked. Choose other lyrics, or dismiss the ones that are right.

Fix a song's lyrics

Wrong lyrics, or none? Find the song, then choose other lyrics, hide them, or go back to automatic. The choice applies in every app that plays from this server.

Genre normalization

Downloads arrive with whatever genre the source had: YouTube categories like “Music” or “People & Blogs”, hyper-specific tags, or seven genres at once. This collapses them into a list you can browse. Rules are tried top to bottom and the first match wins, so put the specific ones above the general ones. Applies to new downloads; files already in the library keep their tags.

Normalize genres
Off by default, because this rewrites a tag you may have curated.
Genres per track
The default keeps what a file already has, so switching normalisation on does not throw away accurate tags. Set it to 1 for one broad genre per track, which is what makes browsing useful on a library whose tags are a mess.
When nothing is left
Clear removes the genre, which is the point: without it, junk that maps to nothing survives forever. Leave keeps whatever was there, and Unknown writes a label instead.
Label for unknown genres
Fallback source
Where to look when a file has no usable genre left. Last.fm uses the top tags it already caches, and needs an API key but not radio.
Blocklist
Extra values that are never a genre, comma separated. YouTube categories, format tags and years are already handled.
Mapping rules
Drag to reorder, or focus a handle and use the arrow keys. A rule with an empty genre drops the value instead of mapping it.

Re-tag the existing library

The settings above only apply to new downloads. This applies them to files that are already in your library. Start with a preview: nothing is written until you look at the list and say so.

Which files
“Downloads Octo made” only touches files Octo created. “The whole library” also rewrites your own rips and purchases, and asks you to type the music path to confirm.
You changed which files. Preview again before applying.
There is no undo for anything but the genre. Writing a tag rewrites the whole tag block, so an unusual field the tag library does not understand is lost on the first save and cannot be restored. Undo is matched by file path, so a file you move afterwards stays changed. Your own backup of the music folder is the only complete safety net.
Preview
Walks every file and shows what would change. Writes nothing.
Apply
Available once a preview has finished, for the same files and rules it previewed.

Mixes

Genre and decade playlists drawn from each listener's own library, shown beside the radio stations and drawn again on a schedule. Octo serves them itself: nothing is written to Navidrome, and a listener cannot edit one by accident.

Which mixes

A mix per decade

Search & download

Search wait / per-peer timeout seconds
How long to wait for peer responses, and how long each of up to 5 peer downloads may take.
Min file size bytes / extension
Filter out clip-sized fakes and prefer a file type.

Verify downloads

Fingerprints each finished download and asks AcoustID what it actually is before it joins the library. A peer that sends a different recording gets that file remembered and never tried again. Off by default.

Verify downloads
Catches covers, karaoke versions, live takes and mislabelled compilation tracks, which all survive the existing length check. A track AcoustID has never heard of is always accepted, never rejected. YouTube downloads are identified too but never rejected, since there is no second candidate to try.
AcoustID API key
Free from acoustid.org/new-application. Without a key the fingerprint lookup is skipped; the length check and its rejection memory still work.
Minimum match score percent
How sure AcoustID must be before its answer may reject a file. Raising this makes Octo more permissive, not less: weaker matches are ignored rather than acted on. Default: 85.
Tag from MusicBrainz
On a confident match, write the matched recording's title, artist, album and year over the source's own tags instead of trusting them.
Name files from the match
On a confident match, also name the file from the matched recording: artist folder, title, album and track number, so the path and the tags agree. A canonical name is not always the one you file under, which is why this is off. Only files Octo downloads and confirms; nothing already in your library is renamed.
Send confirmed fingerprints to AcoustID
When you Keep a track from Review that AcoustID did not know or was not sure of, send its fingerprint with the MusicBrainz recording it belongs to, so the next person gets a confident answer. Only the fingerprint, its length, the recording id and the file format leave Octo; never a file name, a path or a username. Nothing is sent in rehearsal mode, for a track AcoustID named as something else, or when no single MusicBrainz recording fits.
AcoustID user key
Your own key, from your profile at acoustid.org/api-key once signed in. Submissions are credited to it. The application key above is not enough on its own.
Catch fake lossless files
Checks the spectrum of every download that claims to be lossless for the cutoff a lossy encoder leaves, the sign of an MP3 converted to FLAC. A likely transcode is passed over for another lossless copy when a peer has one, and kept, noted as transcoded, when none does. Works without verification or an AcoustID key. A recording that is simply quiet up high is never called fake. On by default.
Rejected peers
Files a download proved were the wrong recording. Entries lapse on their own after 30 days; clear them if a track has stopped being fetchable and you think this list is why.

Library actions

Fix a wrong download from the player you are already using, instead of coming back here. Add the track to one of Octo's action playlists and it gets handled.

This removes files. Nothing is deleted outright: a removed file moves to a quarantine folder inside your music directory and is only really deleted once it is older than the retention window. Even so, this acts on files Octo did not download, on one tap in a music client with no confirmation dialog. Leave the rehearsal mode on until you have read a run.

Who and how

Enable library actions
Off by default. Needs a Navidrome admin credential under Music server, because finding the file behind a track is an admin-only lookup. Star ratings act as soon as you save. Action playlists start being watched after a restart.
Rehearsal mode
Do everything except touch a file, and write down what would have happened. Turn this off only once a run looks right.
Who may trigger actions
Navidrome usernames, comma separated. An empty list means nobody, which is why the feature will not save as enabled without at least one name here.
Action playlists
Octo keeps one private playlist per enabled action for each allowed user. Adding a track to one requests that action.
Playlist name prefix
So the action playlists sort together. Leave empty for none.
Star ratings as commands
Worth leaving off. A star is a one-tap gesture with no confirmation in any client, and rating a track you dislike is an ordinary thing to do. Five stars means Keep, which removes nothing, so the top of the scale is always safe. Applies as soon as you save.
Where a star counts
Only in Octo's playlists makes a star a command only on a track sitting in Review or Duplicates, where the only reason to rate it is to answer; everywhere else a star is just a rating. Automatic does that while either playlist is on, and counts a star on any track otherwise, which is how ratings worked before they existed.

Review

Octo asks about the downloads you can settle by listening: AcoustID had never heard the recording, was not sure of it, or heard a different one in a YouTube download. Each allowed user gets a playlist of their own. Needs library actions on.

Review playlist
Answer by adding a track to an action playlist, by Keep (its playlist, or five stars), or by removing it from Review, which means "fine, stop asking". Nothing in Review is ever acted on by itself. Takes effect at the next check, no restart.
Playlist name
Prefix for Octo's playlists
Sets the playlists where Octo asks you something apart from the action playlists, where you tell Octo something. Leave empty for none.
At most tracks
How many questions one playlist holds at once. The rest wait their turn, so a busy week arrives as a queue rather than a wall.

Duplicates

Recordings your library holds more than once, side by side in a playlist, the copy worth keeping first: lossless before lossy, then the higher bitrate. Octo only points them out. Needs library actions on.

Duplicates playlist
Two files count as copies only when they carry the same MusicBrainz recording and are the same version, so a live take, a remix or a radio edit is never one. Remove a copy you do not want with an action playlist; Keep, or taking a copy out of the playlist, means the copies are on purpose and stops Octo asking about them.
Playlist name
Look every hours
How often Octo walks the library for copies. The walk only reads.
Look now
Walk the library straight away rather than at the next interval. What it found shows under Questions.

The actions

Rename them, switch them on individually, and choose which star count asks for each. Set a rating to 0 to leave that action playlist-only. Keep removes nothing: it answers Review with "this is right", and switches itself on with Review unless you set it.

Lidarr

Use an existing Lidarr server for track and album hearts. Lidarr must already have working indexers and a download client.

Album-level acquisition

Lidarr cannot search for one track. Hearting a single external song resolves its release and imports the full album. Octo never deletes or retags Lidarr's files, but it does move each imported track into the folder layout chosen under Library folder, so Lidarr may later list those tracks as missing.

Reachable from the Octo container, for example http://host.docker.internal:8686.

Raw config

Edit the settings file directly. Same JSON the form-by-form UI writes to — useful for power-users who'd rather hand-write a section than click through tabs, or for diffing/copying config across hosts.

File path

The file lives at /app/config/settings.json inside the container. The host bind-mount is at ./octo-config/settings.json next to your docker-compose.yml — you can vim/nano it there too. Changes hot-reload within ~500ms; settings flagged restart-required still need a restart.

Passwords and keys show here in plain text, except the Navidrome admin password. Don't screenshot or share this page.

settings.json

Top-level keys: Subsonic, Library, Server, Soulseek, Lidarr, YouTube, LastFm, Metadata, Genre, LibraryActions, Notifications, ListenBrainz. Leave "(saved, not shown)" as it is to keep what is stored: the admin password, the Last.fm shared secret, and each Last.fm session key. Radio remains inside LastFm; pinned rows are the ordered LastFm.DiscoveryStations array and should be edited as complete objects with stable Id, Name, Enabled, and Tags fields. Anything you set here overrides the corresponding env var until removed.

About

What this is and where things live.

Octo is a Subsonic API proxy that augments your existing Navidrome library with discovery and on-demand downloading. Search includes external recommendations alongside your local songs; "Radio" on any song fans out via Last.fm and previews via YouTube; heart music you don't own and Octo acquires it through Soulseek, YouTube or your existing Lidarr server.

Version

You are running Octo unknown. Include this in any bug report. Releases are dated, so 2026.07.29 is the release cut on that day.

Settings file

Anything you change in this UI is persisted to /app/config/settings.json. That file overrides env vars on next read. Editing it by hand also works — changes hot-reload.

Hot-reload vs restart

Settings marked Restart take effect after Octo restarts; everything else applies within about a second of saving. Anything waiting on a restart is listed at the top of every page, and the Restart button in the sidebar applies it.

Sign in to browse
Browsing folders needs a Navidrome admin account. Octo checks it with your Navidrome server and never stores it.
